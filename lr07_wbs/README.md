## 1. Вихідні дані та стеля годин

Дата T0 = 2026-11-09 — планове припущення, не дата фактичного старту чи дедлайн викладача. Календар: понеділок–п'ятниця, без урахування свят.

| Роль | Зайнятість | Стеля за 20 тижнів, год | WBS, год | Нерозподілена місткість, год |

Стеля = (0,5 + 1 + 1 + 1 + 0,5) × 20 × 40 = **3200 годин**. Корінь WBS містить **1400 годин = 43,75% стелі**. Це оцінка робіт обмеженого пілоту, а не кошторис оплати всіх 20 тижнів. Нерозподілені години не є вільним календарним буфером: послідовні залежності та доступність конкретної ролі обмежують строк. Резерв місткості потрібен для уточнень, супроводу та непередбачених дефектів; додавати функції без оцінки впливу не можна. Вартість не виводимо із цих годин до встановлення ставок у ЛР16.

Ледь не пропущена робота — перевірка відкату при розгортанні: для сервісу бронювання недостатньо показати успішний запуск. T-22 має дати процедуру відкату з перевіркою збереження вже створених заявок.

Поза обсягом: закупівля обладнання, ремонт аудиторій, автоматичне розв'язання всіх конфліктів розкладу, переписування системи деканату, нативний мобільний застосунок, експлуатація без дозволу власника джерела та InfoSec. Це відповідає статуту. S-14 включена як уточнення захисту від конфліктів, уже зафіксоване в ЛР6. Повідомлення, окремий адміністративний аудит, розширення доступності, облік недоступного обладнання, повтори, календар і аналітика залишені в REL-2. Базова перевірка доступності обладнання та журнал рішень залишаються частиною REL-1.

## 4. Критичний шлях

CPM: ES = max(EF попередників), EF = ES + duration; назад LF = min(LS наступників), LS = LF − duration. Повний резерв = LS − ES. День 0 — початок 2026-11-09, EF позначає межу після останнього робочого дня; у календарі `finish_date` — дата останнього дня роботи. Віха стоїть наприкінці дня попередника.

| Показник | Значення |
| --- | --- |
| Тривалість графа | **100 робочих днів** |
| Початок | 2026-11-09 |
| Завершення | **2027-03-26** |
| Строк V06 | 20 × 5 = **100 робочих днів** |
| Перевищення | **0 днів** |
| Буфер до строку | **0 днів** |

Є **два критичні шляхи**. Спільний початок: T-02 → T-03 → T-06 → T-07 → T-11 → T-12. Далі паралельні гілки T-13 → T-14 та T-15 → T-16, обидві по 15 днів. Спільне завершення: T-18 → T-19 → T-20 → T-21 → T-22 → T-23 → T-24. Кожен шлях: 10+5+10+8+8+10+10+5+20+5+5+0+2+2+0 = 100 днів.

**Формально вкладаємося, але без запасу.** Будь-яка затримка критичної роботи переносить приймання, якщо не змінити план. Прискорення тільки однієї з двох паралельних критичних гілок не скорочує загальний строк. Для скорочення спільної частини насамперед перевіримо можливість раннього інтеграційного тестування частинами або тимчасового збільшення QA; це потребує нового ресурсного розрахунку та погодження вартості. У базовий план непогоджене збільшення команди не включене.

Максимальний резерв — **T-25: 46 днів**, бо тест-дизайн завершується на EF=20, а інтеграційні перевірки починаються на ES=66. Цей резерв не витрачаємо автоматично: ранні тести допомагають виявити помилки вимог. Документація T-17 має 20 днів; PM T-01 — 6. Для T-04/T-05/T-10 резерв 6 днів означає математичну гнучкість графа, але не скасовує управлінський gate W6.

T-05 — не формальне очікування до дати. Якщо дозволу немає, сценарій успішного доступу, на якому побудовано граф, перестає бути дійсним: PM фіксує no-go для живого бронювання, погоджує новий план. Можливе тільки явно позначене навчальне демо. Отримання дозволу тут **не стверджується**.

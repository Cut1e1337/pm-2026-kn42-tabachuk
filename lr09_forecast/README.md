## 2. Як рахувалася симуляція

| Поле | Значення |
| --- | --- |
| Інструмент | власний скрипт Python, `lr09_forecast/monte_carlo.py` |
| Прогонів | 10 000 на кожен сценарій, `random.Random(2026)` для відтворюваності |
| Що тягнеться випадково | velocity одного з моїх спринтів, 8 або 16, з поверненням |
| Як рахується дата прогнозу | для «весь перший реліз» кінець спринта 1 (2026-10-16) плюс (P − 1) × 14 днів; для залишку кінець спринта 2 (2026-10-30) плюс P × 14 днів |

Ядро циклу:

```python
def sprints_needed(remaining, history, rng):
    n = 0
    while remaining > 0:          # вихід, коли залишок дійшов до нуля або нижче
        remaining -= rng.choice(history)
        n += 1
    return n

res = [sprints_needed(remaining, history, rng) for _ in range(10000)]
p50 = sorted(res)[ceil(0.50 * len(res)) - 1]
p85 = sorted(res)[ceil(0.85 * len(res)) - 1]
```

Повторити: `python lr09_forecast/monte_carlo.py`, а з шляхом до `lr09_reference_velocity.csv` скрипт додатково рахує три прогони з розділу 5.

Перевірка руками, що цикл рахує правильно. На залишку 50 і velocity {8, 16}: за 4 спринти треба щонайменше три «16» з чотирьох, імовірність 5/16 = 31%; за 5 спринтів вистачає однієї «16» з п'яти, 31/32 = 97%, але кумулятивно на п'ятому спринті 81%, бо частина прогонів закінчилась раніше. Звідси P50 = 5 і P85 = 6, саме це дав скрипт.

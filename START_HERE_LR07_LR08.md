# Як використати пакет ЛР7–8

Пакет підготовлено для `Cut1e1337/pm-2026-kn42-tabachuk`, Табачук Олександр, КН-42, V06.

1. Розпакуй ZIP. Усередині — папки `lr05_charter`, `lr06_backlog`, `lr07_wbs`, `lr08_poker`, `tools` та звіт перевірки.
2. У своєму локальному репозиторії скопіюй ці папки поверх однойменних із заміною файлів. **Не видаляй увесь репозиторій**: ЛР1–4 і ЛР9–18 до архіву не входять. Папки ЛР5–6 потрібні, бо виправляють схему й зв'язки для нових робіт.
3. Прочитай `REVIEW_LR01_LR08.md`. Звір сценарій конверта 1 з фактичною умовою ЛР8: оригінальні файли завдань у доступних матеріалах не знайдені.
4. Відкрий термінал у корені репозиторію й виконай команди нижче (у Windows зазвичай `python`, у Linux `python3`).

```bash
python tools/validate.py lr05_charter
python tools/validate.py lr06_backlog
python tools/validate.py lr07_wbs
python tools/validate.py lr08_poker
python tools/verify_lr07_lr08.py
```

У ЛР5–6 лишаються пояснені попередження X-14 та BL-9. У ЛР7–8 помилок і попереджень немає; WBS-4 позначене як ручна перевірка.

Після перевірки додай файли до git:

```bash
git add lr05_charter lr06_backlog lr07_wbs lr08_poker tools/verify_lr07_lr08.py REVIEW_LR01_LR08.md START_HERE_LR07_LR08.md VALIDATION_LR01_LR08.txt
git commit -m "Complete LR07 WBS and LR08 estimates; align LR05-LR06 schemas"
git push
```

Пакет сам нічого не завантажує на GitHub; зміни в цьому сеансі зроблені лише у підготовлених файлах. Здавати потрібно файли в репозиторії, а не ZIP як єдиний файл. Дати комітів не підміняються.

## Коротко для захисту

- **ЛР7:** WBS описує результат і трудомісткість; календар додає тривалості й залежності; CPM показує роботи без резерву. Є два критичні шляхи через паралельні гілки захисту/скасування та погодження/станів, після них спільне QA. Сума 1400 годин не дорівнює тривалості: граф займає 100 робочих днів.
- **ЛР8:** за кожною історією три сценарії O/M/P; PERT=(O+4M+P)/6 округлюється до картки Фібоначчі. Після сценарного уточнення інтеграції S-09 оцінка зросла 8 → 13, а сума релізу 61 → 66 SP.
- **Чому 66 SP не означає чотири спринти:** 20 SP — лише планова ємність варіанта, а інтеграція, послідовність і QA обмежують календар. Фактичної velocity ще немає.
- **Що забороняє запуск:** немає підтвердженого джерела зайнятості, залишилися blocker-дефекти або не виконані перевірки прав/конфліктів. Демо на тестових даних не дорівнює продуктивному релізу.
